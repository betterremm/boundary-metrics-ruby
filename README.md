# Анализатор метрики граничных значений для кода на Ruby

Программа на **Python** с графическим интерфейсом (**tkinter**). Разбирает исходный код
на Ruby, строит детализированную схему алгоритма (ГОСТ 19.701-90: один оператор — один блок)
в виде ориентированного графа и считает метрику граничных значений:

* **Sa** — абсолютная граничная сложность;
* **So** — относительная граничная сложность, `So = 1 − (v − 1) / Sa`.

## Состав

```
boundary_core.py        — ядро (парсер Ruby → граф → метрика), без зависимостей; работает как CLI
boundary_gui.py         — графический интерфейс (tkinter)
tests/analyzed.rb       — анализируемая программа лабораторной (те же циклы, ветвления, case/when)
tests/fig1_case.rb      — контрольный пример из методички (Sa = 10, v = 7, So = 0.4)
tests/test_core.py      — автотесты
```

## Запуск

```bash
python3 boundary_gui.py                 # окно приложения
python3 boundary_core.py tests/analyzed.rb --dot scheme.dot   # консоль + экспорт схемы в Graphviz
python3 tests/test_core.py              # тесты
```

Требуется Python 3.8+ с tkinter (Windows/macOS python.org — уже есть; macOS Homebrew:
`brew install python-tk`; Debian/Ubuntu: `sudo apt install python3-tk`).

В окне: «Открыть .rb файл…» / «Загрузить пример» → «Анализировать». Справа — Sa, So и v,
три вкладки: сложности всех вершин, свойства подграфов вершин выбора, блоки схемы с переходами.
«Экспорт схемы (.dot)» сохраняет граф для Graphviz (`dot -Tpng scheme.dot -o scheme.png`).

## Как строится схема

| Конструкция Ruby | Блоки схемы |
|---|---|
| `a += b`, вызовы, присваивания | действие `a = a + b` |
| `puts` / `print` / `p`, `gets` | вывод / ввод |
| `while c` / `until c` | условие `c ?` + тело + возврат к условию |
| `for k in a..b`, `n.times`, `upto`, `downto`, `each` | инициализация переменной цикла, условие, тело, изменение переменной |
| `loop do … end` | блок «цикл loop», тело, выход по `break` |
| `if / elsif / else`, `unless` | условия, вложенные в ветку «нет» |
| `case / when` | вложенные условия (по одному на `when`) |
| `x if c`, `x unless c`, `x while c` | условие `c ?` и блок `x` |
| `break`, `next`, `return` | отдельный блок с переходом на выход / продолжение цикла |

Номера вершин идут в порядке следования операторов; 1 — «Начало», последняя — «Конец».
`def`/`class`/`module`/`begin` в схеме «прозрачны»: их тело разбирается как обычные операторы.

## Метрика

* Положительная степень вершины — число исходящих дуг. Степень ≤ 1 — принимающая вершина
  (сложность 1, у конечной — 0), степень ≥ 2 — вершина выбора.
* Граф разбивается на максимальное число подграфов: вход только через вершину выбора,
  у подграфа есть нижняя граница — вершина, достижимая из любой другой вершины подграфа
  (ближайший общий постдоминатор).
* Скорректированная сложность вершины выбора — число вершин её подграфа, включая нижнюю границу
  (сама вершина выбора входит в подграф, только если она лежит на цикле).
* `Sa` — сумма скорректированных сложностей всех вершин; `So = 1 − (v − 1) / Sa`.

Для `tests/analyzed.rb`: v = 38, Sa = 70, So = 33/70 ≈ 0,471.

## Ограничения

Предполагается стандартный стиль оформления: ключевые слова управляющих конструкций в начале
строки, `end` на отдельной строке. Не поддерживаются многострочные выражения с переносом,
heredoc, присваивание результата `if`/`case` (`x = if …`), тернарный оператор разворачивается
в схему не как условие, а остаётся частью оператора.
